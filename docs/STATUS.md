## 交易日曆：2027 年還沒得產（有時效，v0.7.17 起）

`data/calendar.json` 從 v0.7.17 起是**多年格式**：

```json
{ "generatedAt": "…", "source": "…", "years": { "2026": { "tradingDays": [...], "closed": [...] } } }
```

`makeCalendar()` 兩種格式都讀得懂（使用者手機上可能還存著舊的單年檔）。
`covers()` 的判準是「這一天的年份在 `years` 裡」，不是「以某個年份開頭」。

**實測（2026-09-17）：證交所的 `openapi/v1/holidaySchedule` 目前只有民國 115 年（2026）的 27 筆，
一筆 116 年（2027）的都沒有。** 所以現在跑 `npm run build-calendar -- --year 2027` 會失敗，
而且它**應該**失敗 —— 產一份「整年都開市」的假日曆比沒有日曆更糟：
每個國定假日都會被當成交易日去抓資料，然後把抓不到當成異常。

在證交所公布之前，唯一的防線是提前警示（`market.calendarRunway()`，門檻
`CALENDAR_WARN_DAYS = 45`）：**2026-11-16 起**，總覽的當日損益卡與設定頁會出現
「開休市日只到 12/31（剩 N 天），之後會無法結算，請更新 App。」

### 要做的事

1. 第四季（通常 11～12 月）證交所公布 2027 年休市日之後，跑：
   ```bash
   npm run build-calendar -- --year 2027
   ```
   **它是併入，不是覆蓋** —— 2026 那份會原封不動留著。
2. 跑 `npm run datatest`、`npm run roctest` 確認多年份都對得上。
3. bump、部署。警示句會自動消失（`runway.warn` 變 false）。

如果拖到 2027-01-01 還沒更新：畫面會說「開休市日只涵蓋 2026 年，今天不在範圍內。
更新 App 之後就會恢復。」—— 除權息同步與定期定額待確認也會一起停，但**資料不會壞**，
更新之後會自己補回來。

## 工作慣例（常設規則，給每一個接手的工作階段）

1. **使用者已授權自行執行**查詢、新增檔案、搬移檔案、git 操作（建 repo、commit、push、部署 Worker），**不必逐項請示**。只有「刪除使用者資料」「花錢」「動到其他專案（TripQuest、JLPT_App）」才要問。
2. **重大決策開多代理投票**（現行做法見下方「開發流程慣例」第 4 條）：架構、資料結構、部署方式、需付費或註冊的服務 → 開 **3 個 Fable 5.1（`claude-fable-5-1`）代理**、同一份 prompt、各自獨立、多數決；分歧採保守；決議寫進回報與本文件。
3. **Fable 額度用盡就自動改用 Opus 5，不要停下來問。** 代理因 429／quota 失敗 → 自動改 `claude-opus-5` **整批重跑**（投票要在同一模型上才可比），回報中註明「因 Fable 額度用盡改用 Opus 5」。只有 Opus 5 也不可用時才暫停。
4. **測試不得有假斷言。** 每條斷言都要能用突變測試證明它真的會紅：把對應邏輯改壞（例如拿掉除息參考價、讓上櫃代號顯示價格、給試算器加預設報酬率），測試必須失敗；修回去必須綠。檢查器（禁用詞過濾、代號判斷）要有**對照組**：餵已知該被抓到的輸入，斷言真的抓到。「應該是 0」的斷言旁邊要有「母體非空」的斷言。註解不是斷言。
5. **繁體中文介面**；文案誠實——拿不到的資料就寫「尚未取得」「不支援」，不顯示 0、不用舊資料冒充新資料。
6. **不得出現任何投資建議、目標價、買賣建議**——AI 輸出、UI 文案、試算器預設值、說明文字全部適用。
7. **不規劃也不實作任何券商帳密、下單、轉帳功能。**
8. 沿用 JLPT_App／TripQuest 技術路線：原生 JS ES Modules ＋ IndexedDB ＋ Service Worker，無框架、無打包；`h()` 全 textNode、URL 屬性白名單；CSP `script-src 'self'`；外部請求一律 `AbortSignal.timeout` ＋ 降級。
9. 每版流程：`npm run bump -- stockdiary-vX.Y.Z`（**一次改四處**：`js/version.js`、`sw.js`、`index.html` 的 `?v=`、`package.json`）→ 跑**受影響的**測試＋這次新突變（見「測試範圍」；全套只在 Yolin 叫時跑）→ commit/push → `until curl -s https://yolin0513.github.io/stockdiary/js/version.js | grep -q "vX.Y.Z"; do sleep 5; done` 等線上換版 → `npm run sweep`。
   （2026-09-18 更新：以前寫「bump sw.js VERSION → npm test」，那是 v0.7.10 測試範圍政策之前的做法。）
10. 打真網路的測試（TWSE、RSS、Anthropic）**不進 `npm test`**，另開 `npm run livecheck`；TWSE 請求 ≥ 2 秒間隔，測試也一樣，**不要連打**（社群共識 3 次／5 秒會被封 IP）。

## 測試範圍：平常只跑受影響的，全面檢測由使用者叫（v0.7.10 起）

使用者的指示：「全部專案不用每次上線都做全面測試，只需要針對此次調整的部分做測試，
我會測到一個進度就請你全面檢測。」

### 平常上線

只跑**受影響**的測試，加上這次新增／修改的斷言所對應的那幾條突變。

```bash
node scripts/<受影響的測試>.mjs

# 突變：讓它自己從 git diff 算出受影響的是哪幾條（建議）
node scripts/mutationtest.mjs --changed          # 相對 HEAD（含還沒 commit 的改動）
node scripts/mutationtest.mjs --changed main     # 相對某個分支

# 還是可以手動挑（除錯時比較快）
node scripts/mutationtest.mjs --only <這次的突變關鍵字>
```

`--changed` 的挑選規則（`scripts/affected.mjs`，純函式，`shelltest` 有斷言盯著）：
突變要改的那個檔被改到、突變對應的測試檔被改到、或**那支測試碰得到的任何模組**被改到 ——
三者有一個成立就挑。第三條最重要：沒有任何測試直接 `import` `js/money.js`，
它全是經由 `settle.js`／`dividend.js` 間接用到，只看直接相依的話，改它會一條都挑不到。

**人工挑會漏**（慣例 28 就是漏了一支 `pathtest`），所以預設用 `--changed`，
手動 `--only` 留給除錯。兩者都**不是全綠**，輸出會自己把這句話印出來。

**沒有放寬的那一條：新的斷言仍然必須經突變驗證會紅。** 少跑的是「跟這次無關的那些」，
不是「這次該有的驗證」。一條沒有被突變證明過會紅的新斷言，跟沒有寫是一樣的。

## 接手者最容易做錯的事

1. **除息日不改用參考價 → 生出等於息值的假虧損。** 當日損益的基準在除權息日必須是 `TWT49U` 的參考價（或前收 − 息值），不是前一日收盤。這是自製記帳最常見的錯，M2 必須有突變測試。
2. **上櫃／興櫃代號靜默顯示價格。** TWSE 的端點對上櫃代號可能回空資料或錯誤，若程式把空值當 0 或拿到別的東西就會顯示錯的數字。不支援的代號在任何畫面都不能出現價格，總和要標「不含 N 檔」。
3. **試算器出現任何「建議報酬率」**，包括 placeholder、範例值、「常見 5%」、「歷史平均」，或 AI 幫忙填。全部是投資建議。欄位預設空白，測試斷言 DOM 不含那些詞。
4. **除權息日曆用錯表。** `TWT49U` 是結果表，只有已發生的除息日；日曆要用 `TWT48U` 預告表。兩張表欄位不同，各寫解析器、各有樣本測試。
5. **「今日收盤尚未公布」時顯示 0 或用昨天冒充今天。** 盤後幾點資料才出來要靠 M0 實測；門檻前開 App 要明講「尚未公布」並保留昨天的結算日期。
6. **AI 輸入夾帶股數、金額、成本。** 只給代號、名稱、產業、當日漲跌％；一旦給了金額，模型就會開始「幫你算該不該加碼」。
7. **TWSE 連打被封 IP。** 回補多檔多月時一定 ≥ 2 秒一次；測試不打真網路；`livecheck` 也要節流。
8. **金鑰進了匯出檔。** `secrets` 必須是獨立 store 且所有匯出路徑結構性讀不到它，並有 `secret-leak-test`。
9. **非同步畫面沒有守門 → 按了按鈕跳到別頁。** 見下面那一節，這是實際發生過的 bug。
10. **測試「等到有東西出現」就當作畫面換好了。** `#view` 裡上一頁的內容本來就還在，這種等待**等於什麼都沒等到**，量到的是上一頁。要等**這一頁自己的**標記（標題、`data-card`）。這條假斷言讓 9. 藏了很久。
11. **以為 `page.setOfflineMode(true)` 就是離線。** 它**管不到 Service Worker 自己發的 `fetch`** —— SW 照樣連得到測試伺服器。要真的離線就把伺服器關掉，而且加一條「網路真的斷了」的對照斷言。
12. **`noneOf` 的母體是「有問題的那幾個」。** 沒問題時母體是空的或只剩一個佔位元素，那條斷言就等於什麼都沒檢查。母體要是**全部**（`layouttest` 掃 84 組就要拿 84 組當母體），另外再加一條「每一組都真的量到東西」。
13. **反例太弱，突變被別條規則順便擋掉。** 「拿掉金鑰前綴檢查」那條突變原本不會紅，因為測試用的反例太短、被長度檢查擋掉了。寫反例時要問：**這個案例只有我要測的那條規則擋得住嗎？**
14. **掃描器把註解當成程式碼。** 「程式碼裡不准出現 X」的稽核要先去掉註解（`scripts/srcscan.mjs`），不然等於罰人寫註解；但去註解時**不可以把網址裡的 `//` 也吃掉**（`https://…` 會整段消失，該抓的就抓不到）。
15. **Windows 上 `proc.kill()` 殺不掉孫行程。** `npx.cmd` 那層殼死了，`wrangler`／`workerd` 會活下來佔住連接埠，跑幾次就堆一堆殭屍。用 `taskkill /T`。
16. **突變寫死版本號。** 每 bump 一次就有幾條突變「找不到要改的程式碼」而過期，那段期間對應的斷言等於沒被驗證。版本一律從 `js/version.js` 讀。
17. **突變的 `test` 代號跟檔名對不起來。** 症狀是「基準不是綠的，而且沒有任何 ✗ 明細」，看起來像測試壞了，其實是 `scripts/<代號>.mjs` 不存在。檔名、npm script、突變代號三者要一致。
18. **清測試資料只清 `EXPORTABLE_STORES`。** 那份清單**不含 `settle` 與 `closes`**（刻意的，它們是算得出來的快取，不進備份）。清完以為是乾淨的，其實上一個情境的結算與收盤價都還在，下一個情境就讀到別人的資料。要清就清 `db.STORE_NAMES` 全部。而且**同一個瀏覽器的分頁共用 IndexedDB** —— 開新分頁不等於新資料庫。
19. **清完資料沒有重新載入頁面。** 開機時 App 自己會跑一次 `store.update()`，把「已結算到今天」記在**記憶體**裡。只清資料庫的話那份記憶還在，後面的 `store.update()` 會直接回「已是最新」，什麼都不做 —— 測試於是量到一片空白，看起來像功能壞了。清完要 `page.reload()`。
20. **只測模組，沒測呼叫端有沒有傳。** `buildUserContent` 對大盤與個股漲跌％處理得好好的、單元測試也全綠，但 `js/views/news.js` 根本沒傳那兩個欄位，缺了一段時間都沒人發現。**契約的兩端都要有測試**：模組測「給了會怎樣」，另外要有一條從**按鈕按下去**開始、斷言真的送出去的內容。
21. **「所有可點的都 ≥ 44px」只寫在註解裡。** `uikittest` 開頭列了四條守則，第 4 條是這個 —— 但實際上只驗了切換開關那一顆。於是 `.btn-sm` 長期是 36px，而它正好用在最常按的那幾顆：確認扣款、確認股利、取消確認、修改、停用。**寫在註解裡的規則要有一條斷言對得起來**，而且要掃全頁（7 頁 × 標準與特大字級）。
22. **`fmtPct()` 收的是百分比數字，不是比例。** 傳 `0.0133` 進去會印出「0.01%」——正確答案是 1.33%。小一百倍，而且畫面上看起來完全正常（一樣有小數、一樣有 %）。要傳 `ratio * 100`。
23. **改了空狀態，等「有資料才會出現的東西」的測試會永遠等不到。** 總覽在沒有持股時改成只畫「開始使用」那張卡片之後，`shelltest` 等 `#view .big-number` 直接逾時 60 秒。等待條件要挑**兩種狀態都存在**的東西（標題、`data-card`），或者先把資料種好再等。
24. **用負的 margin 撐大觸控區，會讓相鄰的兩個疊在一起。** 「引用：[n1] [n3]」那兩個小連結用 `padding: 12px 8px; margin: -12px -2px` 撐到 44px，結果左右各疊 2px —— 點在中間會開到錯的那一則。只能往**上下**擴（`margin: -12px 0`）。`layouttest` 的「沒有任何兩段文字疊在一起」抓到的。
25. **清單列用 flex-wrap 排版，右邊的數字會被擠到下一行。** 左側寬度不固定（代號 4 或 5 碼、名稱 2～7 字、有沒有產業標籤），只要撐開一點，`.row-side` 整組就換行 —— 那一列變兩倍高、跟別列對不齊。**右側要有自己的欄**（`display: grid` + `minmax(0,1fr) max-content`），左欄超出時自己截斷，不要去推右欄。
26. **「溢出」與「重疊」兩種掃描都看不到「換行」。** 換行的那一列包得好好的：沒有超出畫面、也沒有疊到別人，只是變成兩倍高。實測過 —— 把持股列的格線拿掉（還原成使用者回報跑版的那一版），`layouttest` 照樣 10/10 全綠。**版面的判準不只有「有沒有爆出去」，還有「同一個清單裡對不對齊」**：右側數字要跟代號同一行、右緣要對齊、每一列高度要一致。
27. **fixture 裡沒有最寬的組合，等於沒掃。** `layouttest` 原本三檔持股全是 4 碼代號、名稱最長 3 字 —— 使用者真正會看到的 `00878 國泰永續高股息`（5 碼 ＋ 6 字）根本不在樣本裡。**掃版面的樣本要放最長的那一個**，不是隨便三筆。
28. **受影響的測試少跑一支，斷言就悄悄過期。** v0.7.12 把「資料狀態」從總覽搬到設定頁，我只跑了 calcviewtest／uikittest／layouttest／racetest／shelltest／calctest —— **漏了 pathtest**（它 import views/home.js）。於是 pathtest 路徑 1 裡比對「還沒有持股」那一句的斷言變成永遠失敗，一直到下一批才被發現。動到 view 就要把**所有 import 它的端對端測試**都跑過（`grep -l "views/<檔名>" scripts/*.mjs`）。
29. **斷言比對整句文案，文案一改就紅。** 上面那條的根因不只是漏跑 —— 那條斷言寫成 `includes('還沒有持股')`，貼著某一句會被搬走的字串。改成驗**語意**（`/開始使用|還沒有持股|尚未結算/`）之後，文案再怎麼搬都還在守同一件事。
30. **用 shell heredoc 產生含 regex 的程式碼 —— 這是目前最危險的一種筆誤。** `\s` 很容易變成 `\\s`，而在 regex 裡那不是「空白」，是「一個反斜線接著字母 s」。**它不會報錯**：程式跑得過、測試是綠的，那條斷言只是從此再也不會命中任何東西。實際發生過兩條，而且守的都是最重要的事 —— scenariotest「畫面上的當日損益沒有生出一個數字」、holdingtest「畫面上沒有『報酬率』後面接著一個值」，兩條從寫下來到被發現都沒有檢查過任何東西。
    · **源頭上避免**：含 regex 的程式碼一律用 Write 工具直接寫檔，不要經過 shell。這一批的修正全程沒有用 heredoc。
    · **事後擋住**：`shelltest` 有一段「沒有跳脫壞掉的 regex」掃 `js/`、`js/views/`、`scripts/` 共 83 個檔。判準是「regex 字面值裡出現兩個反斜線 ＋ 類別字元」，而且會跳過註解與字串（mutationtest 的 find／replace 帶的是別的檔案的原始碼片段，那裡就該有兩個反斜線）。
    · 那個判準自己也很容易寫錯 —— 第一版只匹配一個反斜線，83 個檔全部誤報。**所以它有兩條對照組**：認得出壞的、不會誤報好的。寫檢查器的時候，檢查器本身也要有對照組。
31. **`everyOf([1], () => true, …)` 是 `ok(true, …)` 換了件衣服。** 述詞是常數、母體是寫死的，永遠不會失敗，卻計進通過數。`assertaudit` 的分類只看母體大小，看不出述詞是常數 —— 四支測試的結尾都有一條。要講「跑到最後一行」就用 `note()`（不計入斷言數）。
32. **修好一條假斷言之後，一定要用突變證明它現在真的會紅。** 不驗證的話，你只是把它從「永遠通過」改成「可能還是永遠通過」。這一批修完的兩條都補了對應的突變：「沒填平均成本的也硬算未實現損益」→ holdingtest 紅；「把跳脫壞掉的 regex 放回」→ shelltest 紅。
33. **「先清空再逐列寫入」會在寫壞的那一列把使用者的資料丟掉。** `applyImport` 的語意是取代，所以它 `clear()` 之後才開始 `put()`。一份「外層格式完全合法、只有某一列缺主鍵」的備份檔會走到：holdings 已經空了 → `put()` 丟 `DataError` → 使用者原本的持股不見了，只剩壞檔裡寫得進去的那幾列，而 changes／plans 還是舊的 —— **資料庫進入自相矛盾的狀態**，畫面上卻只有一句沒翻譯的 IndexedDB 錯誤。實測過：匯入前 `0050、2330`，匯入後只剩 `1101`。
    · 修法是**動手之前就把每一列驗完**（`validateImport` 逐列檢查 `db.keyPathOf(store)`），整份拒收，而不是寫到一半才發現。
    · 錯誤訊息要回答使用者當下最急的那件事：**「你現在的資料沒有被動到」**，再講是哪一個項目的第幾列少了什麼。
    · 通則：任何「清空 → 重寫」的流程，**驗證必須整段跑在 clear 之前**。只要有一列會失敗，就一列都不要動。
34. **突變過期有第二種形狀：find 找得到、改得下去，但改的那一行已經沒人走了。**
    `mutationtest` 只檢查 find 在檔案裡出現幾次 —— 出現一次就當作這條突變有效。
    但「程式碼還在」不等於「那段程式碼還有作用」。實際抓到兩條：試算的「帶入」功能
    在 v0.7.11 改成**每檔分別設定**之後，畫面欄位的值來自 `leg.*`（`legCard` 的
    `value: leg[key]`），而那兩條突變還指著 `state.*`：`state.startValue` 只剩寫入、
    沒有任何地方讀它；`state.growthRate` / `state.yieldRate` 根本不存在。
    於是突變「成功套用」、測試「照樣全綠」，而對應的兩條斷言
    （帶入的市值 323,100、成長率與配息率必須留白）從改版那天起就沒再被驗證過。
    · 這種過期**比 find 找不到那種難發現得多**：find 找不到會直接失敗並講出「這條突變過期了」，
      而這種只會靜靜地通過。
    · 怎麼發現的：跑 `--changed` 時它們是唯二沒變紅的。**「突變沒讓測試變紅」要當成兩種可能來查** ——
      斷言是假的，或**突變改錯地方了**。這次是後者，斷言一直是好的。

    · **怎麼分辨是不是這個病**：看空白畫面的頂列是不是還停在 index.html 寫死的「StockDiary」。

    · `js/bootguard.js` 開機看門狗：**刻意是普通 script、沒有任何 import**，所以不會跟 module 圖一起死。

      再給「重新載入」「清快取再載入」。畫面有東西就不出手。
    · `pathtest` 路徑 11 是真實重現：全新 context（沒有 SW）＋ `serve.mjs` 把 `js/store.js` 打成 404 →

    · 通則：**「走網路才拿得到」的東西，在換版與離線的路上一律要有可退的快取**；而任何「畫錯誤畫面的程式碼」
      都必須放在會壞的那張圖之外。
40. **`String.prototype.replace(字串, 字串)` 會把替換字串裡的 `$$` 吃成一個 `$`。**
    用腳本改測試碼時，把含 `page.$$eval(` 的一段當替換字串塞回去，出來的是 `page.$eval(` ——
    語法完全合法、只是行為變了（`$eval` 回單一元素，`.map` 不是函式）。這批實際踩到：
    A8 的 calcviewtest 補丁用 `${anchor}` 把原本那行 `$$eval` 重新塞回去，連原本好的那行一起壞。
    · `$$`、`$&`、`` $` ``、`$'`、`$1` 在替換字串裡**全部是特殊序列**。
    · 要原樣塞進去就用 `split(a).join(b)`，或 `replace(a, () => b)`（函式回傳值不解析特殊序列）。
    · 這跟第 30 條（heredoc 吃反斜線）是同一族：**經手的工具會偷改內容的字元**，而且不報錯。
      含 `$`、反斜線、反引號的程式碼，寫檔前後都要 grep 一次確認字元還在。

## 非同步畫面的守門（v0.5.2，實際發生過的 bug）

使用者回報「點『管理定期定額計畫』會直接跳回主頁」。根因不是路由壞掉，是
**每個 view 都是 async 的，卻沒有人檢查「畫到一半使用者已經走掉了」** ——
最後畫完的那個贏，於是網址是新的、畫面是舊的。三條路徑都會產生同一個症狀：

1. 開機的 `store.update()` 回來後重畫首頁，`here === '/'` 只在那一瞬間檢查一次；
   之後 `import` ＋ 讀 IndexedDB 還要幾百毫秒，使用者在這段空窗點任何按鈕都會被首頁蓋掉。
2. 慢的舊 view 醒來之後照樣把自己畫上去。
3. 過期的 view 還能 `navigate()` 把使用者從他選的那一頁拉走（`holding.js` 查不到代號時）。

守門在 `js/router.js`：`gen`（每導覽一次 +1）與 `paintGen`（正在跑的 view 是哪一代），
兩者不相等就代表過期。**同一時間只跑一個 view**（`runLatest` 迴圈），`paintGen` 才不會
被下一次導覽改掉；跑完發現又有人換頁就再跑一次最新的，所以最後一定停在對的那一頁。

規則：
- **任何一頁都不准自己 `mount(#view)`**，一律走 `js/shell.js` 的 `render()`（守門在那裡）。
  `shelltest` 有靜態稽核擋這件事，連還沒寫的新頁也擋得到。
- 開機／資料更新後要重畫，走 `router.refresh()`，**不要自己 import 那一頁來畫**。
- 新增路由時要同步補 `shelltest` 的 `EXPECT_TITLE`（少一條會失敗，不會靜默略過）。

## 版本參數與模組圖：帶不帶版本要一致（v0.5.3）

`index.html` 載入的是 `./js/app.js?v=<版本>`（版本參數是 HTTP 快取鍵）。由此推出兩條**硬規則**：

1. **`js/app.js` 是進入點，不准被任何模組 `import`。** 用 `'../app.js'`（沒帶參數）
   import 它，瀏覽器會當成另一個網址再求值一次 —— `boot()` 跑兩次、路由註冊兩次、
   **TWSE 被打兩輪**。v0.5.2 真的發生過，線上跑了約半小時。view 要的東西放 `js/shell.js`。
2. **`index.html` 裡每個網址帶不帶版本，要跟模組圖實際請求的一致。**
   `js/app.js` 與 `js/views/*.js` 帶（動態 import 有 `${V}`）；其餘模組被靜態 import，
   不帶。不一致的話 `modulepreload` 會預載一個根本不會用到的網址：多抓一份，
   而且真正要用的那份完全沒被預熱。

兩條都有 `shelltest` 靜態稽核擋著，各自附對照組。

## 新聞來源的已知狀況（2026-09-11 實測）

**自由財經（ltn）會對 Cloudflare Worker 的 IP 限速。** 當天密集測試之後它回 403，
隔兩分鐘就恢復 200。分辨方式：從一般家用 IP 用**同一個 UA** 打是 200，
所以不是擋 UA，是擋來源 IP／頻率。

處理方式：**不做任何規避**（不偽裝 UA、不換 IP）。Worker 有 10 分鐘快取，
正常使用一小時最多碰上游 6 次，遠低於會被限的頻率；真的抓不到時，
新聞頁會列出「有 N 個來源這次沒抓到」與各自的原因，不會靜默少幾則。

要注意的是：**開發時連續跑 `workertest`／`livecheck` 很容易觸發它**。
看到 ltn 回 502（上游 403）先等幾分鐘再試，不要急著改程式。

## 架構決策：**不**把版本參數推到整個模組圖（2026-09-11，評估後選擇不做）

> 這是**評估過之後決定不做**，不是漏掉。日後想加的人請先讀完這一節。

**現況。** 版本參數（`?v=<版本>`，HTTP 快取鍵）只蓋到兩種網址：
`js/app.js`（`index.html` 直接載入）與 `js/views/*.js`（動態 import 帶 `${V}`）。
中間層 —— `router.js`、`store.js`、`ui.js`、`shell.js`、`db.js`、`prefs.js` 等 ——
是被靜態 `import './x.js'` 拉進來的，**不帶版本**。

**所以還剩什麼風險。** 理論上，在 Service Worker 還沒接手的空窗期（第一次開、
快取被清掉、剛部署完那一下），瀏覽器可能從 HTTP 快取拿到十分鐘內的舊中間層模組，
配上新的 `app.js` 與新的 view。

**為什麼還是不做。** 唯一的免打包解法是讓 `npm run bump` 把**每個檔案裡的
import 路徑**都改寫成帶版本（靜態 import 的 specifier 必須是字面字串，沒有別的辦法）。
代價：

1. 引入一個**原始碼改寫步驟** —— 每次 bump 都動到幾乎每個檔案，diff 變吵、
   `git blame` 變差。
2. 多一種新的失敗模式：**漏改就壞**，而且壞法跟原本要防的 bug 一模一樣。
   用新機制去防舊 bug，結果新機制自己會產生同一個 bug。
3. 邊際收益有限：**SW 一旦接手，本來就是整組一致的**（`versionmixtest` 有實證：
   裝舊 SW、伺服器換新版，畫面上的按鈕與路由表始終一致）。真正的空窗只有
   「SW 還沒接手」那一小段。
4. 那一小段已經有安全網：真的混搭時不會靜默跳首頁，而是出現
   「這個畫面在你目前的版本裡還沒有」＋「更新到最新版」按鈕（見上面那一節）。

**結論：收益抵不過新增的失敗模式，維持現狀。** 使用者 2026-09-11 確認此取捨。

要推翻這個決定的話，先回答一個問題：**漏改一個檔案時，什麼測試會紅？**
答得出來再做。

## 換版實測（`npm run upgradecheck`）

「使用者要做什麼才吃得到新版」不能用猜的。這支把使用者的處境重建出來：伺服器回應帶
`cache-control: max-age=600`（跟 GitHub Pages 一樣）、先裝上舊版並確認 SW 接手、
再把伺服器換成新版、然後模擬關掉 App 再開。實測結論（v0.5.0 → v0.5.2）：

- 開一次就自動換版並重載，**使用者不必做任何事**。
- 若一開 App 就馬上操作，自動換版會讓路（那是刻意的，不然會在使用者手上把畫面抽掉），
  改成跳出「有新版本／點一下更新」提示列，點下去就換好。

`scripts/racetest.mjs` 用「指定某個檔案慢幾毫秒回應」的伺服器把空窗撐開到穩定可測，
除了「塵埃落定後停在哪一頁」，也**在空窗中間取樣**，確保不是「先畫錯的再畫對的」。

## 除權息參考價：兩個來源，畫面上分得開（已上線）

TWT49U 的日期參數無效（`FEASIBILITY.md` §10.8），只給得到「最近一次」的除權息結果。
所以參考價有兩條路，**兩者在畫面上必須分得開**：

| 來源 | `basisSource` | 畫面標籤 | 何時用 |
|---|---|---|---|
| 證交所公布 | `refPrice` | 含除息調整 | 除權息當天（或隔天）開 App 抓到 TWT49U，存進 `events.refPrice` |
| 依公式推導 | `refPriceDerived` | 含除息調整（**參考價為試算**） | 事後回補：用前一交易日收盤 ＋ 預告表的配息與配股率算 |
| 兩條都不通 | `none`（status `exNoRef`） | 「參考價既查不到也算不出來，這一檔沒有計入當日損益」 | 缺前收、或配息金額還沒公告 |

公式 `(前收 − 現金股利 + 增資配股率 × 認購價) ÷ (1 + 無償配股率 + 增資配股率)`，捨去到小數兩位，
已用證交所自己公布的六筆（息 4、權 1、權息 1）逐一核對，完全一致。
樣本在 `scripts/fixtures/refprice-pairs.json`，由 `npm run livecheck` 持續累積。

**不可退讓的一條**：推導不出來時回 `null`，**絕不退回用前一日收盤當基準**。
備援是「補位」不是「退路」。這條有兩個突變盯著（`settle.js` 的兩行）。

## 大盤指數：用 FMTQIK，不是 MI_INDEX（v0.7.7）

「今日觀察」的提示內容需要**大盤當日漲跌％**與**每一檔持股的當日漲跌％**（`PLAN` §7.2）。
兩個端點都拿得到大盤，實測後選了前者：

| | `afterTrading/FMTQIK` ✅ | `afterTrading/MI_INDEX?type=IND` |
|---|---|---|
| 漲跌的正負號 | 點數自己帶（`"-784.00"`） | **藏在 HTML 裡**：`<p style='color:green'>-</p>`，點數本身無號 |
| 百分比 | 沒有，自己算（點數 ÷ 前一日指數） | 有 |
| 一次拿到 | **整個月** | 一天 |
| `date` 參數 | **有作用** | 有作用 |

靠顏色判斷漲跌，上游改個樣式就整片反過來，所以不用 MI_INDEX。
兩邊實測對得起來：115/09/11 收 46,184.85、點數 −755.64，
算出 −1.61%，與 MI_INDEX 自己公布的 −1.61 相同（`parsetest` 有這條對照）。

**請求時機：只有按下「產生今日觀察」時才打一次**，不進開頁的更新流程 ——
那條路徑上每多一個請求，每次開 App 就多一次。

**兩個數字都只認「今天」那一筆**：

- 結算紀錄的日期不是今天（收盤還沒公布、或今天休市）→ 個股一律寫「當日無報價」。
- 大盤那一天沒有 → 提示內容寫「大盤當日漲跌：無法取得（不要推測，也不要當成持平）」，
  **不是把那一行省掉**。省掉的話模型看不出差別，可能自己從新聞標題推一個大盤方向當事實。

個股的漲跌％用結算紀錄裡的 `close` 與 `basis` 算 —— `basis` 在除權息日是**參考價**，
所以除息日不會冒出一個等於息值的假跌幅。

守門：`insighttest` 有一段是**從按鈕按下去**開始的，攔 `window.fetch` 斷言真的送出去的字串
（含「拿錯天」與「結算是舊的」兩個對照情境）；`mutationtest` 有四條對應的突變。

## v0.7.9 的兩項使用者回報

### 1. 持股頁「跑版」—— 根因是排版方式，不是微調

使用者截圖：七列裡有兩列高度是別人的兩倍、對不齊。實測重現之後發現**七列全部**都在換行
（右側數字掉到第一行底下 36～38px，列高 109～112px，正常應該是 52px 一行）。

根因：`.row` 是 `flex-wrap: wrap`，左側寬度不固定而右側沒有自己的欄位。

改法：`.row-holding` 用兩欄格線，右欄 `max-content`、左欄 `minmax(0, 1fr)`。
左欄超出時自己截斷（名字先被截，代號與標籤保留 —— 名字截掉還認得出是哪一檔）。
4 碼與 5 碼代號用 `min-width: 5ch` ＋ `tabular-nums` 對齊。

最窄的機型（320px）配大／特大字級時左欄真的放不下，**寧可不顯示也不要疊或截斷**：
均價與產業標籤在那個組合下隱藏（兩者在單檔詳情與產業分布都看得到），當日損益是主角。

**為什麼掃描器沒報**：兩個原因，而且第二個才是關鍵 ——

1. fixture 裡沒有最寬的組合（三檔全是 4 碼、名稱最長 3 字）。
2. **就算補上了也照樣不會報**：溢出與重疊都看不到「換行」。實測過，把格線拿掉、
   用加寬後的 fixture 跑，`layouttest` 仍然 10/10 全綠。

所以除了補 fixture，還加了一項掃描：同一個清單裡**右側數字要跟代號同一行**
（上緣差 ≤ 8px）、**右緣要對齊**（≤ 2px）、**每一列高度要一致**（≤ 2px）。
壞掉那版在這項下面是 `leftSpread 159px`、`maxDrop 36px` —— 紅得很明顯。

### 2. 試算「自動帶出相關欄位」—— 只帶事實，不帶假設

| 帶 | 為什麼可以 |
|---|---|
| 每期扣款金額、每月扣款次數、手續費率 | 他自己在定期定額裡設定的 |
| 目前部位市值、目前股價 | 最後一次結算的結果（已經發生的事實） |
| 標的 | 直接列出他的計畫當按鈕，不必打字 |

| 不帶 | 為什麼不行 |
|---|---|
| **年化價格成長率** | 對未來的假設。給了預設值等於我們替他預測 |
| **年化配息率／殖利率** | 同上 |

帶入之後畫面會列出「帶了哪幾格」，並且**明講哪兩格沒帶、為什麼**——
不要讓他以為整張表都填好了。那段文字裡不可以出現「建議」兩個字，
就算是「不會給建議值」也不行（掃描器只看字面，畫面上出現那兩個字也容易被誤讀）。

順帶修掉的：試算的手續費率上限原本是 `0.999`，等於什麼都沒擋 ——
填 `0.1425` 會被當成 14.25%。改成跟 `js/plans.js` 同一條線（1%），
並補上一樣的即時換算。**同一個單位陷阱在兩頁，行為必須一致。**

## 對帳調查（第 5 項，**凍結中**）

> 2026-09 上旬 Yolin 回報，至今未結案。**在 Yolin 提供資料之前，不准為了讓數字對上而改任何結算或成本的計算**
> （凍結範圍逐檔逐函式列在 `SPEC_全面優化.md` §0；Yolin 原話：「在他給資料之前，絕對不要為了讓數字好看去動任何結算或成本的計算」）。
> 調查步驟的草稿在 `docs/SPEC_對帳調查.md`。

### 回報的數字

| | 國泰 App | StockDiary | 差 |
|---|---|---|---|
| 市值 | 1,843,795（+114.66%） | 1,847,666（+115.17%） | **SD 多 3,871** |
| 成本 | 858,937 | 858,685 | **SD 少 252** |

Yolin 原本把 1,843,795／1,847,666 講成「損益」—— **那兩個數字是市值**：
1,843,795 ÷ 858,937 − 1 ＝ 114.66%、1,847,666 ÷ 858,685 − 1 ＝ 115.17%，兩邊的百分比都對得上「市值 ÷ 成本」。

### 已經確定的

- **成本差 −252 幾乎可以確定是買進手續費**：StockDiary 的成本是「成交價 × 股數」，**設計上不含手續費**（讀程式確認）；
  以 0.1425% 打約 2 折估算約 245 元，跟 252 很接近。畫面上已經講明（總覽 `data-note="costExcludesFee"`，v0.7.13 前後）。
- **已排除**：待確認的扣款／配股不會灌進股數（結算只計 `status === 'confirmed'`，讀程式確認）。
- **配股稀釋均價的算術是對的**：`eventtest` 情境 5b 手算 25,000 ÷ 1,049 ＝ 23.832221163（截斷到小數第九位），程式一致，總成本誤差 1.3e-8 元。

### 還沒解釋的

- **市值 +3,871**。可能的方向（都是推論，沒有驗證）：兩邊用的收盤價不是同一天、國泰的市值有扣預估賣出手續費與證交稅、某一檔股數不一樣（例如一筆配股或定期定額兩邊一邊有一邊沒有）。
- 要逐檔才分得出來 —— 所以卡在資料。

### 需要 Yolin 提供

1. StockDiary 的備份 JSON（設定 → 匯出備份檔；**不含金鑰**）。
2. 國泰 App 上**逐檔**的股數、成本、市值（截圖即可），以及看的時間點。
3. 國泰的手續費折數（例如 2.8 折、低消 20 元）。

## 環境與工具陷阱（2026-09-16～18 踩到的）

- **Windows 上 node 的 `/tmp` 是 `D:\tmp`**，不是 Git Bash 的 `/tmp`。bash 寫到 `/tmp/x`、node 讀 `/tmp/x` 會讀不到。暫存檔一律放 Session 的 scratchpad，用絕對路徑。
- **`SP=... node a.js && node b.js`** 的環境變數只給第一個指令；要跨 `&&` 用 `export SP=...`。
- **Bash 工具擋掉「`sleep N` 接著別的指令」**。等線上換版用 `until curl ... | grep -q vX; do sleep 5; done`。
- **背景指令接 `| tail -N` 的話，輸出要等整個跑完才寫出**，中途看 output 檔是空的 —— 不是當掉。
- **`mutationtest` 會改寫工作目錄**：跑的期間不能編輯檔案、不能並行跑別的測試；每條突變要跑一次完整的對應測試，pathtest 的突變一條要好幾分鐘。
- **`git` 對中文檔名預設跳脫**（`\345\205\250…`）：`git -c core.quotepath=false`（`mutationtest --changed` 已內建）。
- **檔案裡有 NUL 字元，`grep` 與 `git diff` 都會把它當二進位**，review 看不到內容（calcviewtest 以前就是這樣，v0.7.17 換成 `|||`）。
- **內建瀏覽器的分頁會留著舊版的 SW**：線上實機驗證前先確認 `APP_VERSION`，不對就清 SW 與快取再重載（批次 4 驗 CSP 時第一輪量到的是 v0.7.17 的舊程式）。
- **puppeteer**：不認 `'Shift+Tab'`（要 `down/press/up`）；module 圖有檔案吊死時 `DOMContentLoaded` 永遠不觸發，`page.goto` 不能 await；`page.$eval` 回單一元素、`page.$$eval` 回陣列。
- **`--changed` 挑不到「時間走過去」造成的失敗**（第 35 條）；`assertaudit` 也看不出來。全面檢測才抓得到。
- **證交所 `holidaySchedule` 在 2026-09-17 只有民國 115 年**（見「交易日曆」那一節）。

### 界線（`divrecordtest` 守著）

查詢過去配了多少是**事實**，很有用。但多走一步就變成投資建議：

- **不自動填任何試算欄位**（執行期斷言：查詢前後每個欄位的值都沒變）
- **不提供「帶入」按鈕** —— 只要是我們替他把歷史配息換算成配息率，那個假設就是
  我們構造的，按鈕只是把責任偽裝成他的選擇
- **畫面上一個百分比都不出現** —— 除以股價就是殖利率，殖利率就是預期報酬的語言
- **不算平均，只做合計** —— 加總是事實，平均是推論（而且中位數 1 筆算平均沒有意義）
- **不年化**
- 兩種來源分開：「公司公告的」（元/股）與「你自己實際領到的」（元），
  單位不同，永遠不合併計算
