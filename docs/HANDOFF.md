## 5. 只有我們知道的陷阱（換手就會消失，最重要的一節）

### 5.1 不可靠的檢查與數字

1. **逐一計數的峰值不可信**（`scripts/proccount.mjs`、`longrun.mjs` 的 `peakOf`）。被硬殺的程序（含被 Job 連帶殺掉的）不會記「結束」，重播時一直算在場上。**不要拿它的峰值去說「沒超過 4 個」。** 修法（照 MealMate）：結算時逐支核對還記著的程序（PID＋建立時間），有「已不在但沒收到結束通知」的，就把那次峰值作廢。
2. **GV 兩條突變從來沒有證明過任何事。** 帳上「被抓到」是逾時被誤判成紅，已作廢。單跑 `gateselftest` 驗不到它們（它們登記在 `mutationtest`、目標檔是 `gatetest.sh`）。
3. **過去 46 份突變 log 沒有逐條耗時**，「耗時偏短＝可能被中斷」的掃法對它們做不到。**這不是「掃過了、沒有偏短的」，是「掃不到」。** `mutlog` 會把舊格式標成 legacy。
4. **2026-09-23「261 條全部變紅」那種整套結果只剩總數**，沒有逐項證據檔，無法複核（共用慣例 §5.7 不符合）。
5. **孤兒檢查（新測試有沒有登記進鏈）這一輪是直接呼叫函式驗的**（`auditjudge.mjs` 的 `chainOf`＋`auditOrphans`），`controltest` 入口那一段沒驗到。
6. **gatetest 26 個情境的隔離「有，但不完整」**：假遠端的 main 不還原（推送成功的情境讓它往前走，起點跟順序有關）；被 git 忽略的檔只手動刪兩種（`git clean` 沒加 `-x`）；19、19b、19c 從沒經過順序對調。
7. **`mutationtest` 跑的期間不比對工作區**：有人中途改檔，結果是混合版本，log 只記開頭的 commit。跑突變時不要動工作區。
8. **程序數上限與記憶體下限都只記不攔**（只有外部的 `memwatch` 會停）。
9. **餘裕表裡 2026-09-21 那幾支只量過一次**，「最長」就是那一次；之後才加的測試（`buildtest`、`entrygatetest`、`plcaltest` 等）耗時**待量**，估值時當成未知。
10. **`fs.rmSync(…, { force: true })` 只忽略「路徑不存在」**、其他錯誤照樣丟例外——這是讀 Node 文件的**推論，沒實測**。
11. **`ls -ld` 印的是最後修改時間，不是建立時間**。STATUS 裡「最早 2026-09-09」「10-02 留下」都要用建立時間重查。
12. **「沒跑」不能寫成「全綠」**：被判成重負載、沒拿許可而停下，就是沒跑。

### 5.2 推送閘門的毛病

- **TOCTOU**：閘門在 fetch 前記下 `LOCAL`，但自查掃的是當下的 `refs/heads/main`，`git push` 推的是推送那一刻的 `main`。中間落地的 commit 會不經自查就公開；第三關會回 3，但那時已經推上去了。**在修好之前：commit 全部做完 → 立刻 `bash scripts/gatepush.sh` → 中間不 commit、amend、rebase。另一個 Session 可能在同一個 repo commit 時，先確認沒人在動。**
- **`scripts/gatepush.sh`、`gatetest.sh`、`buildverify.mjs` 開 `buildtest` 那一行都沒有逾時**。網路卡住時看起來像「還在跑」。
- **入口沒擋 `GIT_` 開頭的環境變數**（共用慣例 §5.13 不符合）：環境裡剛好設了 `GIT_DIR` 之類，閘門可能對著另一個 repo 檢查然後說通過。推送前先確認環境乾淨。
- 推送那一行**不要接管線**（`| tail -1` 會吞掉失敗的回傳值）；要看輸出就看 `.logs/gatepush-last.log`。
- 閘門各關的回傳值：6 殘留突變、4 第零關登記對不上、5 F9 build 登記、1 自查命中、2 推送失敗、3 遠端≠本機。
- **第零關**：動過閘門或驗法檔，要先跑 `bash scripts/gatetest.sh` 全過（會登記雜湊）才推得出去。

### 5.3 工具與環境的毛病

- **裸寫的 `bash` 從 PowerShell 叫可能變成 WSL**（系統目錄底下那支）。本 repo 用 `scripts/resolvebin.mjs` 解成完整路徑；自己叫的時候從 Git Bash 叫。
- **`controltest` 的逾時對照**：每支測試經 jobrun 多約 0.85 秒，所以用 4 秒逾時、假測試忙等 8 秒；改回 1 秒會讓基準本身逾時。
- **Job Object 的等價突變**：拿掉 `jobhelper.ps1` 的 0x2000（關閉時連帶殺）不會有測試紅，因為 Node 自己的 Job 會補上。這是兩道互為備援，**移除任一道之前確認另一道還在**。另一對：`proctree.mjs` 的「子程序比父程序晚建立」＋「只殺可殺清單裡的」。
- **`convtest` 換一台沒有統籌工作區的機器會紅**（讀不到主檔）——刻意的，不要改成靜默跳過。
- **`memwatchtest`（`tools/`，16 項，約 80 秒）同時約 8 個 node，是重負載**，不在 `npm test` 鏈。
- **突變的 `find` 要剛好出現一次**：突變清單自己也寫著同一段字時會變成 2 次，要把下一行一起帶進 `find`。
- **改了斷言就會改到斷言母體**：要照 bootstrap 流程（舊登記表移開、跑綠、`assertreg build`／`stamp`），否則 `checkmutations` 會報預期過期。
- **`doctest` 會把文件裡的「N 條突變」「N 支」當成總數去比對**：寫文件時，不是總數的數字換個說法（例：「打它的有 19 條」「18 個檔」）。**這份 HANDOFF 寫的「42 支」「490 條」是 2026-11-12 的數字**，以 `package.json` 與 `scripts/mutationtest.mjs` 為準。
- **`timeoutscan` 會把 RegExp 的 `.exec(` 誤認成開子程序**，已排除前面是點的 `exec`。
- 平台會不會切斷長跑**沒有保證**；長跑要靠自己的逾時與外部監看。
- **其他陷阱**（2026-09-16～18 的瀏覽器、SW、IndexedDB）：STATUS「環境與工具陷阱」與「接手者最容易做錯的事」1–40 條，那裡寫得很完整，這裡不重複。

### 5.4 回報時容易出的錯

- 把推論寫成結論。回報一律分「實測驗證過的」與「推論的」。
- 「讀程式碼搜過、沒找到」要寫成「在搜的樣式範圍內未見」，並寫搜了什麼、母體多大。
- 轉達者給的分類（「秒級」「輕量」）錯過兩次——沒附數字就先回估值。
- 推翻一個判斷時只改被指出的那一處：錯的判斷通常被複製到好幾處。

## 6. 如果轉達者叫不動了，你該怎麼辦

**前提：專案仍在暫停。** 暫停的意思是不開新工作；Yolin 直接交辦的單項任務照做。

### 6.1 可以自己做的

- 讀任何檔、查 git、跑**非重負載**的測試（秒級檢查、`npm test` 裡受影響的那幾支，不開瀏覽器、預估不到 600 秒）。每次跑之前先自己估工作程序數與耗時。
- 改程式（凍結區除外）、寫測試、寫文件、更新 `docs/STATUS.md`（每一輪結束前都要寫，Session 可能隨時斷）。
- 本機 commit（逐路徑 `git add`，不要 `git add -A`／`git add .`／`git add <目錄>`）。

### 6.2 一定要停下來等人的

| 事情 | 原因 |
|---|---|
| **push**（含部署 GitHub Pages）、`npx wrangler deploy` | `CLAUDE.md` 平時允許直接做，但**專案暫停中**、又沒有轉達者確認——推上去是公開、收不回來。Yolin 直接交辦的才推，而且一律走 `bash scripts/gatepush.sh` |
| **重負載**：GV、`gateselftest`、`memwatchtest`、開瀏覽器的測試、全面檢測、突變整套 | 共用慣例 §5.19，不得放寬；許可原本由轉達者給，叫不動就問 Yolin。**拿不到許可寧可不部署，也不跳過部署前的測試** |
| 刪除使用者資料、刪除已 commit 的檔、刪暫存複本、force push、改寫 git 歷史 | 共用慣例 §2.1、§2.3 |
| 花錢、註冊帳號、綁卡、安裝軟體 | 共用慣例 §2.1 |
| 動 StockDiary 以外的資料夾（`../TripQuest`、`../JLPT_App`、`../MealMate`、統籌工作區只能讀） | `CLAUDE.md` 第 4 條 |

## 7. 金錢與投資：只記錄、不建議

### 7.1 界線

- App 只記錄使用者自己輸入的持股、交易、股利、定期定額，用證交所官方資料算損益。**不提供投資建議、目標價、買賣提示、進出場時機、個股評等。**
- **試算器**（定期定額試算）：報酬率、配息率**一律由使用者自己填**，欄位預設空白，不給預設值、參考值、歷史平均、placeholder、「填入」按鈕。STATUS「接手者最容易做錯的事」第 3 條：連「常見 5%」都算投資建議。
- **集中度**（`js/concentration.js`、持股頁長條圖）：只顯示百分比，**不寫**「過度集中」「建議分散」「風險偏高」。
- **成本與損益**標示為「約略值」（對帳調查的結論：App 算的成本與券商不一定一致，原因已知一部分）。
- 設定頁固定寫：「本 App 不提供投資建議，不顯示目標價，也不做任何買賣提示。」（`js/views/settings.js`）
- 資料來源只用證交所官方端點（`www.twse.com.tw`、`openapi.twse.com.tw`）與 `FEASIBILITY.md` 評估過的新聞 RSS。**不接 Goodinfo、Yahoo 財經這類非官方或會被擋的價格資料。**

### 7.2 程式裡最可能被讀成投資建議的地方（要特別守著）

1. **今日觀察（AI 整理新聞）**——`js/insight.js`、`js/views/news.js`。用使用者自己的 Anthropic API 金鑰，把新聞標題送給 Claude 整理。
   - 標題固定「今日觀察（AI 整理，非投資建議）」，不可改、不可關；底部固定署名（模型、產生時間、未經查證、不構成投資建議）。
   - 兩道防線：系統提示寫明界線（`buildSystemPrompt`）；輸出回來後用 `BANNED` 樣式再掃一次（`scanViolations`／`filterInsight`），命中的整段不顯示。**後線才是主要防線**，模型一定會偶爾越界。
   - **結構性規則：送出去的內容不准有股數、金額、成本**（`buildUserContent` 只取代號、名稱、產業、當日漲跌％）。一旦給了金額，模型就會開始「幫你算該不該加碼」。
   - `scripts/insighttest.mjs` 有對照組：越界句子要擋、正常新聞句子（「三大法人買超」）要放行。**改 `BANNED` 要兩向都驗**，寬了會把整個功能殺成一片「已隱藏」。
2. **新聞來源裡有 Yahoo 股市 RSS**（`workers/sources.mjs` 的 `yahoo`）。它是新聞 RSS、不是價格資料，在 `FEASIBILITY.md` 評估過、Worker 白名單內。**這是我讀程式看到的現況，不是我做的判斷**：`CLAUDE.md` 第 7 條寫「不接 Yahoo 財經」，兩者是否衝突，有疑問就問 Yolin，不要自己拿掉或擴大用途。
3. **API 金鑰**：存在獨立的 `secrets` store，所有匯出路徑結構性讀不到（`secret-leak-test` 守著）。

### 7.3 個人財務資料不得入庫

- repo 是 public。Yolin 與家人**真實的**持股、金額、交易、備份檔內容一律不進 repo（共用慣例 §2.4、附錄 A）。拿真實資料驗證時，寫進 repo 的只能是結論，或換成合成數字。
- **repo 裡的測試資料都是合成的或公開的**：
  - 測試裡的持股（例：`0050`、`2330`、`00878 國泰永續高股息`、`1101`）、股數、成本：**自己造的假資料**，只是挑了真實存在的公開代號。
  - `scripts/fixtures/`：證交所與新聞 RSS 的**公開**回應樣本（`fmtqik-*.json`、`holiday-schedule-*.json`、`refprice-pairs.json`、`rss-*.xml`）；`anthropic-responses.json` 是**合成的**模型回應（用來測禁用詞過濾）。
  - `data/stocks.json`、`calendar.json`、`dividends.json`：從證交所公開資料產生的，不含任何人的持股。
- **不進版控的**：`.private/pii-blacklist.txt`（公開前自查第五類的黑名單，內容就是個資字面，被 `.gitignore` 擋）。新機器上沒有這個檔，自查第五類會停下——取得方式見 STATUS「推送閘門」那一節，**不要為了推送而建一個空的黑名單**。
- 2026-09-21 Yolin 交過一份真實備份 JSON 做對帳調查；**原始資料沒有進 repo**，STATUS 只留結論。
- 推送前除了閘門的機器自查，**自己把新增的文件行看一遍**：機器抓得到金鑰、email、路徑，抓不到「某某持有多少股」這種個資。
